Part A

Principles

Five rules that govern every decision downstream. When a token, a component, or a platform feels off — check it against these first.
source · DESIGN.md DESIGN.md ↗ principles.html ↗
Principle 01
Utility is beautiful. The product's soul comes from making file operations feel premium — not from decoration. A clean transfer row earns more love than any hero illustration.
Principle 02
Clarity over cleverness. Every icon, button, and label has exactly one meaning. Download means to-this-device. Save means to-put.io. Stream means play-without-download. Never mix.
Principle 03
Type carries the weight. We don't have posters, hero art, or metadata to lean on — a filename is the content. GT America does the heavy lifting; mono fonts handle numerics and identifiers.
Principle 04
One look across platforms. What changes between web, mobile, and TV is the engine — focus model, blur support, player ownership. The visual stays put.io.
Principle 05
Voice & restraint. Brand-yellow #FDCE45 is sacred — used for focus, brand moments, and one CTA at a time. Kaomoji stays. Everything else is a variable: subtract before you add.
Read order. Principles → Components → Platforms. Principles set the rules. Components are the reusable pieces governed by those rules. Platforms compose those pieces into the surfaces users actually touch. Source values live in tokens.css; every preview card cites the file it lifts from. Never invent a number.
