put.io design system

A public reference for engineers and designers building put.io on any runtime. Tokens, primitives, and component specs — generic DTCG / CSS / JSON here, native adaptation in each platform repo. Brand-yellow #FDCE45 is the only sacred constant; everything else is a variable.
v0.6 · 2026-05 tokens.css ↗

What this repo publishes

Generic, framework-free design data: tokens (color, type, space, radii, motion), primitives (focus ring, icon set, logo), and component specs (buttons, list rows, transfer states, overlays).

Source of truth is tokens/**/*.tokens.json. This repo generates CSS, DTCG JSON, flat JSON, TypeScript metadata, and Figma-safe exports; platform repos own native adapters.

Part A

Principles

Eight rules that govern every token, component, and platform. When something feels off — check it against these first.
Principle 01

Utility is beautiful

The product's soul comes from making file operations feel premium — not from decoration. A clean transfer row earns more love than any hero illustration. Beauty has to come from the utility itself.
Lean on type, spacing, motionDon't add hero art
Principle 02

Content-agnostic by default

put.io is the cloud's download folder, not a media library. No posters, no album art, no curated metadata, no "watched" state. Users upload whatever — video, audio, archives, ISOs. The browser treats every file the same.
Use filename + size + dateNo codec / quality / poster badges
Principle 03

Raw filenames stay raw

Never parse The.Wire.S03E04.1080p.x264-GROUP.mkv into "The Wire · Season 3". The user uploaded that name; it is the truth. Render it in Berkeley Mono and let typography make it legible. On TV, mono + tracking, not enrichment.
Render verbatim, mono, ellipsis-on-overflowNever rewrite, parse, fake metadata
Principle 04

Clarity over cleverness

Three actions, three icons, three labels — never overlap. Download = to-this-device. Save = to-put.io cloud. Stream = play-without-download. One verb per icon, one icon per verb.
Unambiguous verbs & iconsNever reuse ⬇ for two actions
Principle 05

Type carries the weight

No posters, no thumbnails, no curated art to lean on — typography IS the content. GT America does UI & body. GT America Mono does numerics (sizes, speeds, durations). Berkeley Mono does filenames & identifiers.
Three families sans · UI mono · code monoNo display serif, no script
Principle 06

One yellow at a time

#FDCE45 is sacred — reserved for exactly one CTA per region and the focus ring. Folder icons too, because the yellow folder is the brand-signature in-product. Never use yellow for decoration, dividers, hover wash, or "make this pop".
Use for 1 CTA · focus · folder iconNever two yellow buttons in view
Principle 07

TV is list-first

10ft + D-pad + no metadata = rows, not card walls. Lists let users navigate by filename. Card grids assume thumbnails we don't have. Apple/Plex card UIs solve a different problem — don't copy them.
Default vertical list, focus rowDon't card grids, hero rails
Principle 08

Voice & restraint

Empty states have personality. ᕦ(ò_óˇ)ᕤ stays. Copy is plain, short, English-first. Subtract before you add: if a screen ships without a number or icon, ship it without. Every chrome element earns its keep.
Kaomoji in empty states & footersNo emoji, no decorative SVG, no slop
Read order. Principles → Tokens & primitives → Components → Platforms. Source values live in tokens/**/*.tokens.json; generated CSS/JSON files are artifacts. Never invent a number.

Usage

  • No card walls · no hero rails · no "Continue Watching" if we can't track it
